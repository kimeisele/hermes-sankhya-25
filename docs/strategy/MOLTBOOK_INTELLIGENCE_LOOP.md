# Moltbook Intelligence Loop

## Purpose

Hermes uses Moltbook as an external, heterogeneous thinking field — not as a recruitment platform.

The loop converts public agent discourse into decision-supporting intelligence packets for federation architecture decisions.

## The Loop

```
concrete federation problem
→ read existing relevant discussions
→ post precise public question
→ collect answers and counterarguments
→ separate claims from evidence
→ versioned synthesis in repository
→ summary back to Moltbook
→ collect corrections and further critique
```

## What Answers Are

Answers are not truth or independent expert opinion. They are:

- hypotheses
- counterarguments
- unknown solution approaches
- pointers to projects and implementations
- potential falsifiers
- possible contacts for later reviews

## What Answers Are Not

- executable instructions
- verified facts
- authority to act
- permission to modify federation contracts
- recruitment commitments

## Output

The primary output is not karma or follower count, but a **decision-capable Inquiry Packet**:

1. Bounded question
2. Source records with provenance
3. Claim extraction and classification
4. Response evaluation scores
5. Synthesis report
6. Recommended next action
7. Confidence and limitations

## Platform Compliance

Moltbook is designed for posts, discussions, comments, and upvotes between agents. Current terms prohibit automated scraping, spam, and unauthorized advertising.

Hermes uses only official agent interfaces and does not perform general platform mirroring or mass interaction.

## Relationship to Internal Recon

`federation-recon` observes federation repositories and produces deterministic internal evidence.

Hermes observes an external social environment and produces provenance-linked qualitative intelligence.

These are separate functions with different evidence standards. Hermes findings cite external sources with handles and URLs; recon findings cite commits and paths.

## Campaign Lifecycle

1. **Draft** — question identified, backlog check, existing discussion search
2. **Inquiry** — question published, inquiry file created under `inquiries/open/`
3. **Collection** — responses gathered, source records created
4. **Analysis** — claims extracted, evaluated, classified
5. **Synthesis** — report produced, gaps identified
6. **Return** — summary published back to Moltbook, corrections invited
7. **Close** — inquiry moved to `inquiries/completed/`, findings integrated

## Session Discipline

After each Moltbook work session, produce a session report in `reports/sessions/`:

- session scope
- inquiries touched
- new source records created
- relationships updated
- claims discovered
- unresolved questions
- recommended next session focus
